## 一、项目全景

### 1.1 这个项目做什么？

本项目是一个**基于ROS2 Humble的FR5协作机械臂视觉伺服控制系统**。通俗地说：**让机械臂"看着"摄像头画面，自动对准目标并插入**。

具体场景：模拟鼻腔拭子操作——机械臂末端装有摄像头和工具，通过视觉实时检测鼻孔（体外阶段），对准后进入腔体（体内阶段），在腔体内自主导航前进到目标深度。

### 1.2 为什么分"体外"和"体内"两个阶段？

| | 体外导航（Outside） | 体内导航（Inside） |
|---|---|---|
| **视觉算法** | MediaPipe人脸关键点检测 | APF人工势场法（暗区/亮区分割） |
| **环境特征** | 视野开阔，人脸完整可见 | 视野狭窄，腔体内壁占据画面 |
| **运动策略** | XY平面对准 → Z轴逼近（顺序执行） | 旋转校准 ↔ Z轴推进（交替闭环） |
| **核心挑战** | 人脸角度变化、光照差异 | 目标频繁丢失、腔道弯曲 |

两阶段的视觉方案、控制策略、参数体系完全不同，因此拆成两个独立的ROS2 Node。

### 1.3 硬件组成

| 硬件 | 型号/规格 | 作用 |
|---|---|---|
| 协作机械臂 | 法奥 FR5（六轴） | 执行运动指令 |
| 摄像头 | USB RGB摄像头（640×480，~30fps） | 提供实时视觉反馈 |
| 计算平台 | PC/工控机，Ubuntu 22.04 | 运行ROS2节点和视觉算法 |
| 通信方式 | 以太网，机械臂IP `192.168.58.2` | ROS2 Service + Topic |

## 四、ROS2核心概念详解

> 本节面向ROS2初学者。结合本项目代码，详细讲解ROS2的核心概念。每个概念都配有代码实例和通俗类比。

### 4.1 Node（节点）—— 程序的基本单元

**通俗类比**：一个Node就像一个独立的"工人"。每个工人有自己的工作内容（代码），通过特定方式和其他工人交流（Topic/Service），各司其职。

**本项目中的体现**：

```python
# move_outside_node.py
import rclpy
from rclpy.node import Node

class MoveOutsideNode(Node):            # 继承Node类
    def __init__(self):
        super().__init__('move_outside_node')  # 给节点起名字
```

本项目只有两个Node：`move_outside_node` 和 `move_inside_node`。它们是仅有的两个"ROS2实体"。

**关键认识**：不是所有类都要继承Node。`RobotController`、`VisionSystem`、`APFVisionSystem` 都是普通Python类——它们通过传入Node实例来使用ROS2的通信能力（例如 `RobotController` 的构造函数接受 `node: Node` 参数）。这是一种**依赖注入**的设计模式。

**Node的完整生命周期**（以 move_outside_node 为例）：

```python
def main(args=None):
    rclpy.init(args=args)              # ① 初始化ROS2客户端库
    node = MoveOutsideNode()           # ② 创建节点（内部调用__init__）

    ros_executor = MultiThreadedExecutor()
    ros_executor.add_node(node)        # ③ 将节点注册到执行器
    spin_thread = Thread(target=ros_executor.spin)  # ④ 后台线程驱动节点运行
    spin_thread.start()

    # ⑤ 主循环（摄像头读取 + UI显示）
    while rclpy.ok() and not node.system_terminated:
        node.process_frame()

    node.destroy_node()                # ⑥ 销毁节点，释放资源
    rclpy.shutdown()                   # ⑦ 关闭ROS2
```

### 4.2 Parameter（参数）—— 运行时可调的配置值

**通俗类比**：参数就像"设置面板"。你可以不改代码、不重启程序，就调整机器人的行为。

**本项目的使用方式**（两步走）：

```python
# 第一步：声明参数（在__init__中），给出默认值
self.declare_parameter('max_depth_mm', 50.0)
self.declare_parameter('simulate', True)

# 第二步：获取参数值
self.MAX_DEPTH_MM = self.get_parameter('max_depth_mm').get_parameter_value().double_value
self.simulate = self.get_parameter('simulate').get_parameter_value().bool_value
```

**运行时动态修改参数（不重启节点）**：
```bash
# 查看当前参数值

# 运行时修改参数
ros2 param set /move_inside_node max_depth_mm 60.0

# 启动时传入参数

```

**为什么要用参数而不是全局变量？**
1. 调参时不需要改代码、重新编译、重启节点——在机械臂调试现场极其实用
2. 可以把所有配置集中写在YAML文件中，通过launch文件统一管理
3. 参数自带类型（double/int/bool/string），`get_parameter()` 自动做类型转换

### 4.3 Service（服务）—— 请求-响应式通信

**通俗类比**：Service就像"打电话"。你拨过去（发请求），对方接起来说"好的，办完了"（返回响应）。适合需要确认结果的操作。

**本项目中的使用**：

```python
# robot_controller.py
from fairino_msgs.srv import RemoteCmdInterface

# 创建服务客户端——连接到机械臂控制器的指令通道
self.cli = node.create_client(
    RemoteCmdInterface,
    '/fairino_remote_command_service',
    callback_group=self.client_cb_group
)

# 等待服务上线（启动时）
while not self.cli.wait_for_service(timeout_sec=1.0):
    node.get_logger().info('等待 /fairino_remote_command_service 服务...')
```

**异步调用服务（不阻塞线程）**：

```python
def _call_service(self, command_str, timeout=3.0):
    if self.simulate:
        return True, "0"     # 仿真模式：不真发指令，直接返回成功

    req = RemoteCmdInterface.Request()
    req.cmd_str = command_str

    future = self.cli.call_async(req)   # 异步调用，立即返回Future对象

    # 用Event等待结果（带超时保护）
    event = threading.Event()
    future.add_done_callback(lambda f: event.set())
    if event.wait(timeout):
        resp = future.result()
        return (resp.cmd_res == "0"), resp.cmd_res
    else:
        future.cancel()                 # 超时取消
        return False, "-1"
```

**本项目通过Service发送的指令示例**：

| 指令字符串 | 含义 |
|---|---|
| `CARTPoint(1,100.0,200.0,300.0,0.0,0.0,0.0)` | 将当前位姿存储为基准点1 |
| `PointsOffsetEnable(2,0.5,0,0,0.1,0,0)` | 在基准点上叠加偏移(dx=0.5, dy=0, dz=0, dRx=0.1, dRy=0, dRz=0)，模式2=工具坐标系 |
| `MoveL(CART1,5.0,1,0,0,0,0,0)` | 以5.0mm/s速度直线移动到偏移后的位置 |
| `PointsOffsetDisable()` | 关闭偏移模式 |
| `ResetAllError()` | 清除机械臂所有错误状态 |

**Service vs Topic 的区分原则**：

| | Topic（话题） | Service（服务） |
|---|---|---|
| 通信模式 | 发布-订阅（单向） | 请求-响应（双向） |
| 谁主动 | 发布者一直发，订阅者一直收 | 客户端主动请求，服务端被动响应 |
| 适用场景 | 周期性数据流（传感器、状态） | 指令下发、信息查询 |
| 本项目例子 | 订阅 `/nonrt_state_data` | 调用 `/fairino_remote_command_service` |

### 4.4 Topic（话题）与 Subscription（订阅）—— 数据流通信

**通俗类比**：Topic就像"广播电台"。发布者不需要知道谁在听（甚至可能没人听），订阅者收到消息就处理，不需要回复。

**本项目中的使用**：

```python
# robot_controller.py
from fairino_msgs.msg import RobotNonrtState

# 订阅机械臂状态话题
self.sub = node.create_subscription(
    RobotNonrtState,              # 消息类型
    '/nonrt_state_data',          # 话题名称
    self.state_callback,          # 回调函数（收到消息时自动调用）
    10,                           # QoS队列深度（最多缓存10条消息）
    callback_group=self.sub_cb_group
)
```

**回调函数——当收到机械臂状态消息时**：

```python
def state_callback(self, msg):
    """自动被ROS2调用，更新缓存的机械臂位姿"""
    self.current_pose = [
        msg.cart_x_cur_pos,    # X位置 (mm)
        msg.cart_y_cur_pos,    # Y位置 (mm)
        msg.cart_z_cur_pos,    # Z位置 (mm)
        msg.cart_a_cur_pos,    # 绕X轴旋转 Rx (度)
        msg.cart_b_cur_pos,    # 绕Y轴旋转 Ry (度)
        msg.cart_c_cur_pos     # 绕Z轴旋转 Rz (度)
    ]
```

**工作原理**：
1. 机械臂控制器内部有一个发布者（Publisher），定期把当前位姿发布到 `/nonrt_state_data` 话题
2. 本项目的 `state_callback` 函数会自动被调用，把最新位姿存入 `current_pose` 缓存
3. 运动指令函数（如 `move_xy`）需要当前位置时，直接读缓存，不需要自己轮询

### 4.5 Executor（执行器）—— 驱动Node运转的引擎

**通俗类比**：Node是"工人"，Executor是"工头的调度"。Node只是定义了"收到消息后做什么"，但谁去检查"有没有新消息来了"？是Executor。

**本项目为什么用 MultiThreadedExecutor？**

```python
# move_outside_node.py 和 move_inside_node.py 的 main() 函数
ros_executor = rclpy.executors.MultiThreadedExecutor()
ros_executor.add_node(node)

# 放在后台线程spin
spin_thread = threading.Thread(target=ros_executor.spin, daemon=True)
spin_thread.start()
```

**MultiThreadedExecutor vs SingleThreadedExecutor**：

| | SingleThreadedExecutor | MultiThreadedExecutor |
|---|---|---|
| 线程数 | 1个 | 多个 |
| 回调执行 | 排队串行 | 可并行 |
| 优点 | 简单，无竞争 | 回调不互相阻塞 |
| 适用 | 简单节点 | 多回调、高频数据节点 |

**为什么放到独立线程？**
`spin()` 是一个无限循环（不断检查新消息），如果直接在主线程调用 `spin()`，主线程就被"卡住"了，没法做摄像头显示和键盘处理。放到后台线程，主线程就可以自由做UI。

### 4.6 CallbackGroup（回调组）—— 精细化并发控制

**通俗类比**：多个电话（回调）同时打进来，你可以选择让他们排队等（互斥组），还是交给多个接线员同时处理（不同组并行）。

**本项目为什么用了两个Call​​backGroup？**

```python
# robot_controller.py
self.client_cb_group = MutuallyExclusiveCallbackGroup()  # 服务客户端专用
self.sub_cb_group = MutuallyExclusiveCallbackGroup()      # 订阅器专用

self.cli = node.create_client(..., callback_group=self.client_cb_group)
self.sub = node.create_subscription(..., callback_group=self.sub_cb_group)
```

**效果**：
- 服务客户端（运动指令响应）和订阅器（位姿更新）被分到两个不同的互斥组
- 两个组可以**并行执行**——即使运动指令的响应处理比较慢，位姿更新回调不会被阻塞
- 如果不分两组，默认所有回调在一个组里，串行执行，其中一个慢了就会拖累另一个

## 五、系统架构深入分析

### 5.1 三层线程分工

这是本项目最重要的架构设计：

```
┌──────────────────────────────────────────────────────────────────┐
│                        三层线程分工                               │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│  主线程 (Main Thread)                                             │
│  ├── cv2.VideoCapture.read()      ← 读取摄像头                    │
│  ├── cv2.imshow()                 ← 显示画面（含可视化叠加）       │
│  └── cv2.waitKey()                ← 键盘处理（空格/Q/R）          │
│       │                                                           │
│       │ self.latest_frame (由 data_lock 保护)                     │
│       ▼                                                           │
│  后台处理线程 (Processing Thread)                                 │
│  ├── vision.process_frame()       ← 视觉检测（MediaPipe / APF）  │
│  ├── kalman_filter.update()       ← 滤波平滑                     │
│  ├── 状态机评估                    ← 根据状态和观测决策             │
│  └── 运动指令计算                  ← 生成 dx/dy/dz/rx/ry         │
│       │                                                           │
│       │ 异步任务提交 (task_executor.submit)                        │
│       ▼                                                           │
│  ThreadPoolExecutor (max_workers=4)  ← 异步线程池                 │
│  └── robot.move_xy() / move_z_only() / rotate_tool_frame()       │
│      └── ROS2 Service call_async() ← 发送运动指令并等待结果       │
│                                                                   │
└──────────────────────────────────────────────────────────────────┘
```

**为什么这样设计？**

- **主线程要快**：摄像头30fps意味着每33ms就有一帧新图像，主线程必须快速读取和显示，否则画面卡顿
- **视觉处理可能慢**：MediaPipe单帧推理可能耗时20-30ms，APF图像处理也要10-20ms。如果和主线程放一起，帧率会降到15fps以下
- **运动指令不能阻塞状态机**：机械臂执行一个MoveL可能要几百毫秒，如果同步等待，状态机的帧循环就卡住了。用线程池异步发指令，状态机继续跑

### 5.2 分层解耦：ROS边界最小化

```

│               ROS2 边界层                             │
│  ┌──────────────────────────────────────────────────┐│
│  │  MoveOutsideNode / MoveInsideNode                ││

│  │  - 管理状态机 (当前状态 + 帧计数器)               ││
│  └────────────────────┬─────────────────────────────┘│
│                       │                               │
│  ┌────────────────────▼─────────────────────────────┐│
│  │  RobotController (不继承Node，依赖注入)           ││
│  │  - 接受Node实例创建Service Client和Subscription  ││

│  └────────────────────┬─────────────────────────────┘│
├───────────────────────┼──────────────────────────────┤
│             ROS2 边界 │                               │
├───────────────────────┼──────────────────────────────┤
│  纯Python层（零ROS依赖）│                              │
│  ┌────────────────────▼─────────────────────────────┐│
```

**这意味着**：所有视觉算法、滤波器、状态枚举都**不依赖ROS2**。你可以在一个纯Python脚本中导入并测试它们，不需要启动ROS2、不需要机械臂。这是工程上非常重要的可测试性设计。

## 六、流程详解：不同情况的执行路径

### 6.1 体外导航（move_outside_node）

#### 6.1.1 主流程：从启动到到达目标

```
                           ┌──────────┐
                           │   IDLE   │  按空格启动
                           │   空闲    │
                           └────┬─────┘
                                │ 检测到鼻孔，误差>10px
                                ▼
        ┌──────────────────────────────────────────────┐
        │              ALIGN_XY（XY平面对准）            │
        │                                               │
        │  每帧计算：                                    │
        │  1. 像素误差 err_x = 目标X - 画面中心X         │
        │  2. 像素误差 err_y = 目标Y - 画面中心Y         │
        │  3. 像素→毫米比例 = 12.0mm / 当前鼻孔像素间距 │
        │  4. XY移动量 = 误差 × 比例 × 阻尼系数0.6       │
        │  5. clamp(XY移动量, -2.0mm, +2.0mm)           │
        │                                               │
        │  切换条件：误差 ≤ 10px 且保持 ≥ 3帧            │
        └──────────────────┬───────────────────────────┘
                           │ 条件满足
                           ▼
        ┌──────────────────────────────────────────────┐
        │    TRANSITION_TO_APPROACH（对齐→进近过渡）     │
        │                                               │
        │  过渡帧数：5帧                                 │
        │  ratio = 当前帧序号 / 5                        │
        │  XY移动量 = 全量 × (1-ratio)    ← 逐渐减小     │
        │  Z移动量  = 2.0mm × ratio       ← 逐渐增大     │
        │                                               │
        │  5帧后自动切换到 APPROACH_Z                    │
        └──────────────────┬───────────────────────────┘
                           │ 过渡完成
                           ▼
        ┌──────────────────────────────────────────────┐
        │             APPROACH_Z（Z轴逼近）              │
        │                                               │
        │  每帧计算Z轴步长：                              │
        │  - 鼻翼宽度<300px 且 差距>60px → 步长2.0mm     │
        │  - 鼻翼宽度<300px 且 差距>25px → 步长1.0mm     │
        │  - 鼻翼宽度<300px 且 差距≤25px → 步长1.0mm     │
        │  - 鼻翼宽度≥300px → TARGET_REACHED             │
        │  - Z累计≥150mm → TARGET_REACHED(强制停止)       │
        │                                               │
        │  切换条件：误差 > 20px 且保持 ≥ 3帧 → 退回对齐  │
        │  切换条件：鼻翼宽度 ≥ 300px → 到达目标          │
        └──────────────────┬───────────────────────────┘
                           │ 鼻翼宽度 ≥ 300px
                           ▼
                    ┌──────────────────┐
                    │ TARGET_REACHED   │
                    │   目标已到达      │
                    │ 停止所有运动      │
                    └──────────────────┘
```

#### 6.1.2 异常路径A：目标丢失 → 后退重试

```
任何状态（ALIGN_XY / APPROACH_Z / 过渡）
    │
    │ 连续多帧检测不到鼻孔
    ▼
TARGET_LOST（目标丢失）
    │
    │ 等待 3.0秒（LOST_TIMEOUT_SEC）
    │
    ├── 3秒内目标恢复 → 根据误差判断进入 ALIGN_XY 或 APPROACH_Z
    │
    └── 3秒超时 + 尚未后退过 → RETREAT
            │
            │ Z轴后退 20.0mm（一次完成）
            ▼
        状态停留（等待目标重新出现）
            │
            │ 目标恢复 → 进入 ALIGN_XY（因为误差通常很大）
            ▼
        ALIGN_XY（重新开始对准）
```

#### 6.1.3 异常路径B：连续运动失败 → 自动暂停

```
任何运动指令发送后
    │
    │ robot.move_offset_tool_frame() 返回 False
    ▼
consecutive_move_fails += 1
    │
    ├── < 3次 → 记录错误，继续运行
    │
    └── ≥ 3次 → auto_run = False（自动暂停）
                打印错误日志，等待用户检查
```

### 6.2 体内导航（move_inside_node）

#### 6.2.1 主流程：从盲走到深度上限

```
                           ┌──────────┐
                           │   IDLE   │  按空格启动
                           │   空闲    │
                           └────┬─────┘
                                │ 启动后首先进入盲走
                                ▼
┌──────────────────────────────────────────────────────────────┐
│                  BLIND_ENTRY（盲走进洞）                       │
│                                                               │
│  策略：APF还没看到暗区目标时，小步前进试探                      │
│                                                               │
│  每步行为：                                                    │
│  - 每 0.15秒 沿Z轴前进 2.0mm                                   │
│  - 同时持续用APF检测暗区                                       │
│    - 检测到目标 → blind_goal_consecutive += 1                  │
│    - 没检测到   → blind_goal_consecutive = 0                   │
│                                                               │
│  结束条件A：连续20帧检测到目标 → 盲走完成                       │
│  结束条件B：累计盲走≥20mm → 强制结束（就算没看到目标也不再走）   │
└──────────────────┬───────────────────────────────────────────┘
                   │ 盲走完成
                   ▼
┌──────────────────────────────────────────────────────────────┐
│          TRANSITION_TO_ROTATE（前进→旋转过渡）                 │
│                                                               │
│  过渡帧数：10帧                                                │
│  ratio = 当前帧 / 10                                          │
│  旋转/平移量 = 全量 × ratio（线性淡入）                        │
│  10帧后自动切换到 ROTATE_ALIGN                                 │
└──────────────────┬───────────────────────────────────────────┘
                   │ 过渡完成
                   ▼
┌──────────────────────────────────────────────────────────────┐
│                ROTATE_ALIGN（旋转对准） ↔                      │
│                                                                  │
│  每帧行为：                                                      │
│  1. APF检测暗区目标                                              │
│  2. 卡尔曼滤波目标位置 → goal                                    │
│  3. 计算像素距离 = |goal - 画面中心|                              │
│  4. 计算力场向量（吸引力指向goal + 排斥力推开亮区）               │
│  5. ForceToMotionConverter：力场 → Rx/Ry旋转角 + dx/dy平移量    │
│  6. 异步执行旋转+平移                                            │
│                                                                  │
│  移出条件：像素距离 < 130px 且保持 ≥ 2帧 → 切到前进               │
│  移出条件：单阶段累计旋转 ≥ 2.0° → 切到前进（安全限制）           │
│  移入条件（从ADVANCE_Z）：像素距离 > 180px 且保持 ≥ 5帧          │
└──────────────────┬───────────────────────────────────────────┘
                   │ 条件满足（距离<130px）
                   ▼
┌──────────────────────────────────────────────────────────────┐
│         TRANSITION_TO_ADVANCE（旋转→前进过渡）                 │
│                                                               │
│  过渡帧数：10帧                                                │
│  ratio = 当前帧 / 10                                          │
│  旋转/平移量 = 全量 × (1-ratio)  ← 逐渐减小（线性淡出）        │
│  Z轴前进量   = 0.5mm × ratio   ← 逐渐增大（线性淡入）          │
│  10帧后自动切换到 ADVANCE_Z                                    │
└──────────────────┬───────────────────────────────────────────┘
                   │ 过渡完成
                   ▼
┌──────────────────────────────────────────────────────────────┐
│                ADVANCE_Z（Z轴前进） ↔                          │
│                                                                  │
│  每步行为：沿Z轴前进 0.5mm                                       │
│                                                                  │
│  移出条件（切回旋转）：像素距离 > 180px 且保持 ≥ 5帧              │
│  终止条件：累计深度 ≥ 50mm → MAX_DEPTH_REACHED                   │
└──────────────────┬───────────────────────────────────────────┘
                   │ 累计深度 ≥ 50mm
                   ▼
          ┌────────────────────┐
          │ MAX_DEPTH_REACHED  │
          │   最大深度已到达    │
          │ 停止运动，按R键重置 │
          └────────────────────┘
```

#### 6.2.2 异常路径A：目标丢失 → 阻塞等待 → 后退

```
任何正常导航状态（ROTATE_ALIGN / ADVANCE_Z / 过渡）
    │
    │ 当前帧检测不到目标 (goal is None)
    │ + 卡尔曼预测不可用或已用完5帧预测限额
    ▼
BLOCKED（阻塞等待）
    │
    │ 计时开始：blocked_start_time
    │ 机械臂暂停不动，等目标恢复
    │
    ├── 1.5秒内目标恢复 → 根据状态机正常逻辑切换到对应状态
    │                     （如果是RETREAT状态恢复 → 进入TRANSITION_TO_ROTATE）
    │
    └── 超过1.5秒 → RETREAT
            │
            │ 每步Z轴后退 0.5mm（注意不是一次退完）
            │ 边退边检测目标
            │
            ├── 目标恢复 → 进入 TRANSITION_TO_ROTATE（重新旋转对准）
            │
            └── 一直退到机械臂物理限制或用户干预

卡尔曼预测的特殊路径（在BLOCKED之前）：
    │
    │ 当前帧检测不到目标，但卡尔曼已初始化
    │ + 连续预测帧数 < 5
    ▼
使用卡尔曼预测位置 → goal_is_predicted = True
    │
    │ 力场向量 × 0.3（KALMAN_PREDICT_FORCE_SCALE）
    │ 用缩小的力场继续导航（减少因预测不准导致的碰撞风险）
    │
    └── 超过5帧仍检测不到 → 进入 BLOCKED
```

#### 6.2.3 异常路径B：旋转过限 → 强制切前进

```
ROTATE_ALIGN / TRANSITION_TO_ROTATE 状态
    │
    │ 检查：current_rotation_rx² + current_rotation_ry² >= (2.0°)² ?
    │
    ├── 未超限 → 正常执行旋转对准
    │
    └── 超限 → rotation_safe = False
               │
               └── 状态机跳过旋转，强制切换到 TRANSITION_TO_ADVANCE
                   只前进不旋转（即使偏差还没完全消除）
```

### 6.3 状态切换的核心机制

#### 6.3.1 迟滞切换（Hysteresis）

这是本项目最重要的状态机设计模式：

```
体外例子：
  误差 = 5px  → 在 APPROACH_Z ✅
  误差 = 12px → 在 APPROACH_Z ✅ (因为没超过进入阈值20px)
  误差 = 15px → 在 APPROACH_Z ✅
  误差 = 25px → 切回 ALIGN_XY   (超过了进入阈值20px)
  误差 = 15px → 仍在 ALIGN_XY   (还没低于退出阈值10px，不回APPROACH)
  误差 = 8px  → 切回 APPROACH_Z (低于了退出阈值10px)

体内例子：
  距离 = 100px → 在 ADVANCE_Z ✅
  距离 = 150px → 在 ADVANCE_Z ✅ (没超过开始校准阈值180px)
  距离 = 200px → 切回 ROTATE_ALIGN (超过了180px)
  距离 = 150px → 仍在 ROTATE_ALIGN (还没低于停止校准阈值130px)
  距离 = 100px → 切回 ADVANCE_Z (低于了130px)
```

**为什么需要迟滞？** 没有迟滞的话，如果误差在阈值（比如20px）附近反复横跳——这一帧19px（进入前进），下一帧21px（退回对齐），再下一帧19px...系统就会疯狂抖。两个不同的阈值创造了一个"安全区"，在这个区间内状态保持稳定。

#### 6.3.2 帧计数防抖

```python
# 伪代码逻辑
if 条件满足:
    if state_frame_counter >= MIN_FRAMES:
        执行状态切换
    else:
        state_frame_counter += 1  # 还不够帧数，继续累计
else:
    state_frame_counter = 0  # 条件不满足了，计数器归零
```

这确保状态切换不是因为**某一帧的偶发检测错误**而触发。即使条件满足了，还要"连续多帧"都满足才真正切换。

#### 6.3.3 过渡帧线性淡入淡出

```python
# 体外: TRANSITION_TO_APPROACH
ratio = min(当前帧 / 5, 1.0)
move_x = 全量X * (1.0 - ratio)   # XY从100% → 0%
move_z = 步长Z * ratio            # Z从0% → 100%

# 体内: TRANSITION_TO_ADVANCE
ratio = min(当前帧 / 10, 1.0)
rx = 全量旋转 * (1.0 - ratio)     # 旋转从100% → 0%（线性淡出）
dz = 0.5mm * ratio                # Z前进从0% → 100%（线性淡入）
```

这实现了不同运动模式之间的**平滑切换**，机械臂不会在状态切换瞬间产生急停急启的冲击。

## 七、核心算法深度剖析

### 7.1 MediaPipe Face Mesh（体外视觉）

**代码位置**：`vision_system.py`

**原理**：Google MediaPipe的Face Mesh模型在单张人脸上检测出468个三维关键点。本项目只用其中4个：

```
人脸正面示意图（MediaPipe关键点）：

        358●────────────●129        ← 鼻翼外缘（用于计算鼻翼总宽度）
              ╲        ╱
            279●────●49              ← 左右鼻翼底部基准点
                ╲  ╱
                 ●●                   ← 鼻孔中心（目标落点）
              （插值计算）

关键点索引：
- 279: 左鼻翼底部（pt_base_left）
- 49:  右鼻翼底部（pt_base_right）
- 358: 左鼻翼外缘（left_wing_outer）
- 129: 右鼻翼外缘（right_wing_outer）
```

**目标定位算法**（三选一，由 `target_side` 参数控制）：

```
如果 target_side = 'left':
    目标 = 左鼻翼点(279) 与 鼻小柱中点 的中点
    即：左鼻孔中心

如果 target_side = 'right':
    目标 = 右鼻翼点(49) 与 鼻小柱中点 的中点
    即：右鼻孔中心

如果 target_side = 'center':
    目标 = 鼻小柱中点
    即：两个鼻孔之间的位置
```

**输出三个值**：
1. `(tx, ty)`：目标在图像中的像素坐标
2. `feature_width`：鼻翼总宽度（358到129的像素距离），用于判断是否到达目标
3. `nostril_distance_px`：鼻孔基准间距（279到49的像素距离），用于像素→毫米的动态标定

### 7.2 人工势场法 — APF（体内视觉）

**代码位置**：`vision_inside.py` → `APFVisionSystem`

**核心思想**：将图像空间视为一个"力场"。暗区中心（目标）产生**吸引力**，亮区边缘（障碍物/组织壁）产生**排斥力**。合力的方向和大小决定了机械臂的运动方向和速度。

#### 7.2.1 图像预处理

```python
原始图像 (BGR)
    │
    ▼
_clahe.apply(gray)      # CLAHE自适应直方图均衡化：增强暗区对比度
    │                     # 在腔体环境中补偿光照不均
    ▼
GaussianBlur(7×7)     # 高斯模糊：去除高频噪点
    │
    ▼
预处理完成 → 进入暗区/亮区分割
```

#### 7.2.2 暗区/亮区分割

```python
# 基于灰度百分位数阈值
dark_thresh = np.percentile(gray_img, 8)    # 灰度值最低8% → 暗区
bright_thresh = np.percentile(gray_img, 80)  # 灰度值最高20% → 亮区

dark_mask = 灰度值 < dark_thresh 的像素
bright_mask = 灰度值 > bright_thresh 的像素

# 形态学闭运算（填充小孔，连接邻近区域）
dark_mask = morphologyEx(dark_mask, MORPH_CLOSE, 7×7椭圆核)
bright_mask = morphologyEx(bright_mask, MORPH_CLOSE, 7×7椭圆核)

# 提取轮廓，过滤小噪点（面积<0.5%总面积的忽略）
dark_regions = [面积>0.5%总面积的暗区轮廓]
bright_regions = [面积>0.5%总面积的亮区轮廓]
```

#### 7.2.3 目标选择（从多个暗区中选最优）

```python
def _select_goal(self, regions):
    for each dark region:
        cx, cy = 暗区质心
        area = 暗区面积

        # 打分公式：靠下程度(0.2权重) + 面积占比(0.8权重)
        score = (cy / height * 0.2) + (area / total_pixels * 0.8)

    返回 score 最高的那个暗区质心
```

**设计思路**：在腔体图像中，真正的通路通常在画面下方（靠下），且面积较大。这个打分公式综合了两个因素。

#### 7.2.4 力场计算

**吸引力**（指向暗区目标中心）：
```python
attractive_force = K_ATT(5.0) × (目标位置 - 图像中心)
# 离中心越远，吸引力越大（线性）
```

**排斥力**（远离高亮障碍物）：
```python
对每个亮区障碍物:
    如果图像中心在障碍物内部:
        # 从障碍物质心指向中心的力（固定大小）
        total_repulsion += K_REP × 100 × 单位方向向量

    如果图像中心在障碍物外部:
        找到障碍物轮廓上离中心最近的点
        距离 dist = |中心 - 最近点|
        如果 0 < dist < REP_RANGE(80px):
            # 距离越近，斥力急剧增大（1/dist² 关系）
            repulsion = K_REP × (1/dist - 1/80) × (1/dist²)
            total_repulsion += repulsion × 方向向量

合力 total_force = attractive_force + total_repulsion
```

### 7.3 卡尔曼滤波器（KalmanFilter2D）

**代码位置**：`utils.py`

**数学模型**：标准线性卡尔曼滤波

**状态向量**（4维）：`[x, y, vx, vy]` — 目标位置和速度

**状态转移方程**（恒定速度模型）：
```
x(k+1) = x(k) + vx(k)      ← 新位置 = 旧位置 + 速度
y(k+1) = y(k) + vy(k)
vx(k+1) = vx(k)             ← 速度恒定不变
vy(k+1) = vy(k)
```

矩阵形式：
```
F =
 [[1, 0, 1, 0],
     [0, 1, 0, 1],
     [0, 0, 1, 0],
     [0, 0, 0, 1]]
```

**观测矩阵**（只测量位置，不直接测量速度）：
```
H = [[1, 0, 0, 0],
     [0, 1, 0, 0]]
```

**噪声设计**：
- 过程噪声 Q = 0.05 × I₄：对"目标匀速运动"的信任度较高
- 测量噪声 R = 4.0 × I₂：对"APF单帧检测位置"的信任度较低

Q/R比值 0.05/4.0 = 0.0125，说明滤波器**更信任模型预测，不太信任单帧测量**。这在APF检测噪声较大的场景中是合理的。

**两步操作**：

```python
# 1. 测量更新（正常帧，检测到目标）
filtered_pos = kalman.update(raw_goal)
# 内部：预测 → 用测量值修正 → 输出平滑位置

# 2. 纯预测（丢失帧，检测不到目标）
predicted_pos = kalman.predict_only()
# 内部：只用速度模型外推 → 输出预测位置
# 最多连续预测5帧（KALMAN_PREDICT_MAX_FRAMES），超过则重置
```

### 7.5 ForceToMotionConverter（力→运动转换器）

**代码位置**：`vision_inside.py`

这是体内导航**视觉空间到机器人运动空间**的桥梁。

**转换流程**：

```
APF力场向量 (fx, fy) [像素空间]
    │
    ▼
force_mag = sqrt(fx² + fy²)
    │
    ├── force_mag < 死区10.0  → 输出全零（不运动）
    │
    └── force_mag ≥ 死区10.0
            │
            ▼
        归一化：norm_force = (force_mag - 10) / (1150 - 10)
        clamp到[0, 1]
            │
            ▼
        动态增益计算（非线性曲线）：
            │
            ├── 旋转增益 = 0.001 + (0.012 - 0.001) × norm_force^0.6
            │    (最小值 → 最大值，曲线因子0.6使低力区增益相对更大)
            │
            ├── 平移步长 = 0.02 + (0.15 - 0.02) × norm_force^0.7
            │    (最小值 → 最大值，曲线因子0.7)
            │
            ├── Rx旋转角 = -fy × 旋转增益
            │    Ry旋转角 = fx × 旋转增益
            │    clamp(Rx, -0.2°, 0.2°)
            │    clamp(Ry, -0.2°, 0.2°)
            │
            └── dx平移 = (fx / force_mag) × 平移步长
                 dy平移 = (fy / force_mag) × 平移步长
                 检查阶段累计不超1.0mm

输出：(Rx°, Ry°, dx_mm, dy_mm)
```

**重要符号约定**（需根据实际安装验证）：
- `+fy`（目标偏下方）→ `-Rx`（绕X轴下俯）
- `+fx`（目标偏右方）→ `+Ry`（绕Y轴右转）
- `+fx`（目标偏右方）→ `+dx`（向右平移）
- `+fy`（目标偏下方）→ `+dy`（向下平移）

**非线性曲线的直观效果**：

```
增益
▲
│        ●─────────────────── 最大增益
│      ╱
│    ╱   ← 曲线因子<1：低力区上升更快
│  ╱
│╱
●────────────────────────────→ 归一化力场
0                            1

设计意图：
- 力场很小（接近目标）：用接近最小增益 → 精细微调
- 力场中等：增益快速增长 → 不算大的偏差也能有效纠正
- 力场很大（偏离很远）：用最大增益 → 快速纠正但不失控
```

### 7.6 异常帧过滤（体外）

**代码位置**：`move_outside_node.py` `_processing_loop()`

```python
# 检测到鼻孔位置后，做两重检查：

# 检查1：位置跳跃检测
if 上一帧有检测结果:
    jump = |当前检测位置 - 上一帧检测位置|  # 欧氏距离
    if jump > 90px (MAX_JUMP_PX):
        → 判定为异常帧，丢弃

# 检查2：鼻翼宽度突变检测
if 上一帧有检测结果:
    w_jump_ratio = |当前鼻翼宽度 - 上一帧宽度| / 上一帧宽度
    if w_jump_ratio > 0.40 (MAX_WIDTH_JUMP_RATIO):
        → 判定为异常帧，丢弃
```

这两个检查过滤了MediaPipe偶发的检测跳变（比如人脸短暂移出画面、光照突变导致的误检），防止机械臂因为一个错误检测猛地转向。

## 八、设计合理性、优点与改进方向

### 8.1 设计优点

#### 8.1.1 分层解耦：可测试性强

视觉算法和滤波器**零ROS依赖**。可以在任何Python环境中独立测试APF算法、卡尔曼滤波逻辑，不需要启动ROS2或连接机械臂。这是工程上的最佳实践。

#### 8.1.2 仿真模式：安全高效的开发方式

`simulate=True` 让所有机械臂操作变为日志输出，视觉流水线和状态机逻辑完整运行。可以在没有机械臂的情况下开发、调试、验证逻辑——安全（不会撞）、高效（不用每次连接硬件）。

#### 8.1.3 双节点拆分：职责清晰

体外和体内使用完全不同的视觉算法和控制策略。拆成两个Node让每个节点聚焦自己的任务，参数域清晰，出问题时容易定位。如果放在一个Node里，代码会非常臃肿。

#### 8.1.4 迟滞切换 + 帧计数防抖：工程稳定性

进入条件 ≠ 退出条件（如体外20px进入 vs 10px退出），加上帧计数防抖，双重滤波确保状态切换稳定可靠。这是从实践中总结出的重要经验——没有这些，边界处会疯狂跳变。

#### 8.1.5 动态标定：适应性强

像素→毫米的比例不是固定值，而是用已知鼻孔间距(12mm)和每帧实际检测到的像素间距**实时计算**。这样无论机械臂离人脸多远，比例都是准确的。这比预先标定一个固定值要鲁棒得多。

#### 8.1.6 过渡帧淡入淡出：运动平滑

不同运动模式之间不是硬切换，而是通过过渡帧做线性插值。XY逐渐减小、Z逐渐增大（或反过来）。机械臂不会出现急停急启的冲击。

#### 8.1.7 多重安全保护

| 保护层 | 机制 |
|---|---|
| 急停（软件） | 空格键暂停、Q退出、连续失败3次自动暂停 |
| 行程限制 | Z轴总行程150mm(体外)/50mm(体内)、旋转阶段上限2° |
| 单步限幅 | XY≤2mm/步、Z≤2mm/步、旋转≤0.2°/步 |
| 异常过滤 | 位置跳变>90px丢弃、宽度突变>40%丢弃 |
| 超时保护 | 服务调用3s超时、位姿获取1s超时、目标丢失1.5s/3s超时后退 |

#### 8.1.8 重试/错误恢复机制

运动指令失败后自动清除错误并重试（最多3次），提高了在通信抖动、机械臂偶发错误时的鲁棒性。

#### 8.1.9 卡尔曼预测外推：目标短暂丢失不中断

当APF某帧检测不到目标时，卡尔曼滤波器可以基于历史速度外推预测位置（最多5帧），避免立刻进入BLOCKED/RETREAT。这个机制在实际腔体导航中非常实用，因为组织壁可能短暂遮挡视野。

### 8.2 可改进方向

#### 8.2.1 get_current_pose 的忙等问题

**现状**：
```python
while self.current_pose is None and not self.simulate:
    time.sleep(0.01)  # 10ms轮询
```

**问题**：虽然不是死等（有超时），但sleep轮询仍是"忙等"（busy waiting），不够优雅。

**建议**：用 `threading.Event` 做信号等待：
```python
# 在 state_callback 中 set event
self.pose_ready = threading.Event()

def state_callback(self, msg):
    self.current_pose = [...]
    self.pose_ready.set()

def get_current_pose(self, timeout=1.0):
    if not self.pose_ready.wait(timeout=timeout):
        return None
    return self.current_pose
```
Event.wait() 是不消耗CPU的阻塞等待。

#### 8.2.2 APF局部极小值问题

**现状**：APF在腔体内导航存在理论上的局部极小值问题——当引力和斥力刚好抵消时，机械臂卡住不动。

**当前处理**：BLOCKED超时→后退→重试（被动等待）

**建议**：
- 加随机扰动：检测到合力长时间接近零时，主动加一个小幅随机偏移，帮忙跳出极小值
- 或者检测到卡住时先小幅左右旋转"摆动"，尝试重新建立视觉跟踪

#### 8.2.3 缺少力传感器反馈

**现状**：完全依赖视觉反馈，没有接触力感知。如果在真实鼻腔中，可能有碰到组织壁但不自知的危险。

**建议**：集成一维/六维力传感器，设置力阈值保护——当接触力超过安全阈值时，立即停止或后退。在力-位混合控制中，力反馈的优先级应高于视觉引导。

#### 8.2.4 运动指令独立发送导致的非原子性

**现状**：`_async_rotate_translate()` 将旋转和平移分两次独立调用。如果旋转成功但平移失败，系统状态可能不一致。

**建议**：使用 `move_rotate_and_translate(rx, ry, dx, dy, 0, 0)` 做一次复合运动，`RobotController` 已实现此方法但体内节点没使用。

#### 8.2.5 缺少ROS2 Launch文件

**现状**：两个节点需要分别手动启动，没有launch文件做统一管理。

**建议**：编写 `bringup.launch.py` 或 `.launch.xml`，方便一键启动所有节点，同时把参数从代码中抽到YAML配置文件。

#### 8.2.6 缺少坐标系正式标定

**现状**：像素→毫米的动态标定依赖鼻孔间距(12mm)这个单一已知量。在体内阶段，标定精度会因角度变化而降低。

**建议**：加入完整的**Eye-in-Hand手眼标定**流程（棋盘格 + `easy_handeye` 或类似工具），获得精确的相机→法兰→基座的变换矩阵。

#### 8.2.7 缺少单元测试

**现状**：test目录下只有基础的copyright/flake8/pep257检查，没有功能测试。

**建议**：
- 对 `KalmanFilter2D`、`EMAFilter`、`ForceToMotionConverter` 编写单元测试
- 对 `SystemState` 状态机的每种切换路径编写测试
- 录制一段rosbag数据，做回放测试

#### 8.2.8 QoS未显式配置

**现状**：使用ROS2默认QoS（RELIABLE + KEEP_LAST(10)）。

**建议**：对 `/nonrt_state_data` 订阅可显式配置QoS为 `KEEP_LAST(5)` + `BEST_EFFORT`（允许丢几帧旧数据，只要最新的），因为运动控制只需要最新位姿。

#### 8.2.9 RETREAT 状态体外体内复用但行为不同

**现状**：体外和体内共用一个 `RETREAT` 状态枚举值，但后退行为完全不同（体外一次退20mm，体内每步退0.5mm）。代码中没有明确区分。

**建议**：要么在注释中明确标注两种行为的差异，要么在状态枚举中直接定义 `RETREAT_OUTSIDE` 和 `RETREAT_INSIDE`。

## 九、总结与学习建议

### 9.1 项目技术总结

本项目实现了一个**完整的ROS2视觉伺服闭环控制系统**，核心技术栈包括：

| 技术领域 | 本项目实现 |
|---|---|
| **ROS2通信** | Node、Service（运动指令）、Topic（状态订阅）、Parameter（运行时调参） |
| **ROS2并发** | MultiThreadedExecutor、MutuallyExclusiveCallbackGroup、ThreadPoolExecutor |
| **视觉检测** | MediaPipe Face Mesh（体外）、APF人工势场法（体内） |
| **信号处理** | EMA指数滑动平均、卡尔曼滤波（含外推预测） |
| **控制策略** | 状态机（17种状态）、迟滞切换、帧计数防抖、过渡帧淡入淡出 |
| **运动控制** | 工具坐标系偏移、直线运动(MoveL)、旋转+平移复合运动 |
| **安全工程** | 行程限制、单步限幅、异常过滤、超时保护、重试机制、仿真模式 |
| **软件架构** | 多线程分层架构、ROS/非ROS层严格解耦、依赖注入 |

### 9.2 对ROS2初学者的学习路径建议

基于本项目，建议按以下顺序学习ROS2：

1. **理解Node的基本写法**：看 `move_outside_node.py` 或 `move_inside_node.py` 的 `__init__()` 和 `main()` 函数，掌握 `rclpy.init()` → 创建Node → spin → destroy → shutdown 的生命周期。

2. **理解Parameter**：看 `declare_parameter()` 和 `get_parameter()` 的用法，学会 `ros2 param set` 命令行操作。

3. **理解Service**：看 `robot_controller.py` 的 `_call_service()` 方法，理解客户端创建、异步调用、超时处理。

4. **理解Topic/Subscription**：看 `robot_controller.py` 的 `create_subscription()` 和 `state_callback()`，理解发布-订阅模式。

5. **理解Executor**：看两个Node的 `main()` 函数中的 `MultiThreadedExecutor` 用法，对比 `SingleThreadedExecutor` 的区别。

6. **理解CallbackGroup**：看 `robot_controller.py` 中两个互斥回调组的设置，理解并发控制。

7. **理解Launch文件**：目前项目没有，可以自己写一个练手。

8. **理解TF2坐标变换**：目前项目依赖机械臂SDK封装的工具坐标系。可以研究ROS2的TF2系统如何发布和监听坐标变换。
